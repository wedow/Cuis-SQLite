# fix UnicodeString handling in text binding

Fix apiBindText: to handle UnicodeString (not just ByteString).

Current state: apiBindText: declares char* parameter. Cuis UnicodeString cannot be coerced to char* by FFI, so inserting unicode text like 'café' raises 'Could not coerce arguments'. Additionally, arg size returns codepoint count not byte count.

Fix approach:
- In bindArg:at:in:, convert UnicodeString to UTF-8 bytes before passing to apiBindText:
- Use byte length (not codepoint count) for the size parameter
- On read, consider decoding UTF-8 ByteString back to UnicodeString (or document the limitation)

Note: this depends on understanding how Cuis exposes UTF-8 encoding (e.g., asUtf8Bytes or similar).

## Acceptance Criteria

- UnicodeString values can be inserted as TEXT without error
- Multi-byte UTF-8 characters survive round-trip
- ByteString text still works as before
- Empty UnicodeString round-trips
- Existing tests pass
